## 问题汇总与解答

### 1. 学会看报错

在前几次上机课中，我们在解答同学们的问题的时候也都演示过如何看报错信息，包括如何看错误在第几行以及是什么类型的错误等，其中大部分写代码过程中可能出现的错误都在 [错误合集]({{ '/qa/common-errors.html' | relative_url }}) 中有详细的说明，相信大家已经看到过了。

这几次上机课看下来，主要的报错都是编译错误，原因是大家没能正确编写符合 C 语言语法规则的代码，一般可以根据编译器的报错信息定位错误所在行以及错误原因。常见的编译错误包括：使用未声明的变量或函数、漏用分号、输入了中文字符、括号前后匹配不当，`int mian()` 等写法错误、函数返回值相关问题等等。具体大家参考 [错误合集]({{ '/qa/common-errors.html' | relative_url }})。

### 2. PTA 报错相关

各位在 PTA 提交答案的时候，肯定遇到过类似“运行超时”、“答案错误”、“编译错误”等报错信息，具体的含义各位可以在 PTA 代码框上方“常见问题”中查看。

![PTA 代码框上方的帮助按钮与常见问题入口]({{ '/assets/images/first_quiz/fig1.png' | relative_url }})

![PTA 评分结果及说明]({{ '/assets/images/first_quiz/fig2.png' | relative_url }})

常见的就是“格式错误”、“运行超时”、“编译错误”：

- **格式错误**：提交的代码没有按照题目要求的输入输出格式进行编写，最简单的做法是把示例输出直接粘贴到 `printf` 中，然后把对应的变量替换掉即可。

- **运行超时**：提交的代码在规定的时间内没有运行结束，大概率是写出了死循环，比如 `while(1)`，`1 <= n` 或者循环变量 `i` 没有正确自增等，导致循环无法结束。

    - 运行超时的另一种情况是算法太复杂，比如 C 语言自带的 `pow` 函数较为耗时，对于简单的 `int` 类型的平方/立方，请考虑换用自己实现的计算函数。当然，各位现在的题目都比较简单，暂时还遇不到这种问题。

- **编译错误**：提交的代码没有通过编译，原因多种多样，参考报错自行修正。

- **答案错误**：提交的代码运行结束后，输出的结果和题目要求的结果不一致，大概率是代码的逻辑有问题，建议不要只以题目示例输入输出为准，而是自己构造多种多样的测试用例和边界条件，通过观察输出判断代码逻辑是否正确。

    - 还可以在纸上手推一遍自己的代码，一步一步运行，看看中间变量和最终输出是否符合预期，或者在代码中加入调试信息，打印中间变量的值，看看是否符合预期。

### 3. 作业答疑

各位问的比较多的是作业 4 的编程题 7-4。要求我们统计字符的个数。

#### 常见写法与正确写法

有些同学写出了：

```c
scanf("%d\n", &count);
```

这样的代码，希望通过 `\n` 来吃掉第一行的换行符，但是实际上这种是不对的，应该用一个 `getchar()` 来吃掉换行符，然后再进行下一行的输入。正确的写法是：

```c
scanf("%d", &count);
getchar(); // 吃掉换行符
```

#### 为什么会跳过空格

原因在于，`scanf` 在读取输入的时候，有一个特殊的特性，它会忽略缓冲区前导的所有空白符（空格、回车等），一直到它读取到第一个有意义的字符为止。

然而 `\n` 在 `scanf` 中并不是一个普通的换行符，它不代表我的 `scanf` 只读取一个换行符，而是代表它会一直读取，直到遇到一个非空白符为止。也就是说，如果你在 `scanf` 中使用了 `\n`，那么它会一直等待你输入一个非空白符，这就导致了我们在输入的时候，程序会一直等待，直到你输入了一个非空白符为止。

知道了这个，再去看 7-4 的错误就很简单了，比如我想输入五个字符，那么我的输入就是：

```text
5回车
空格abcd
```

我们期望的输出是：

```text
letter = 4, blank = 1, digit = 0, other = 0
```

这时候我们来看缓冲区，它里边存的是：

```text
5回车空格abcd
```

那么这时候读取 `scanf("%d\n", &count);`，它会读取到 5，但是由于 `\n` 的存在，它会继续读取，直到遇到一个非空白符为止，所以它跳过了回车，跳过了空格，在 `a` 前边停下，这时候，缓冲区里边剩下的就是：

```text
abcd
```

所以你会发现，实际读到的字符数是 4，而不是 5，那么程序就会停下来再等你输入一个非空白符，但是这明显是错误的，所以正确的做法就是在 `scanf` 之后使用一个 `getchar()` 来吃掉换行符，这样就不会影响后续的输入了。

#### 本地运行示例

下边是一个示例代码：

```c
#include <stdio.h>

int main()
{
    int x;
    char ch;

    scanf("%d\n", &x);
    printf("x = %d\n", x);

    ch = getchar();
    printf("ch = %c\n", ch);
    printf("hello world\n");

    return 0;
}
```

在这个代码中，我们先读取了一个整数 `x`，然后立即输出 `x` 的值，然后读取字符 `ch`，并输出它的值，最后输出 `hello world`。那么理想状态下，我们输入 `5回车`，之后，程序应该立即打印：

```text
x = 5
```

然后我们再输入一个字符，比如 `a`，程序应该立即打印：

```text
ch = a
hello world
```

但是各位运行之后会发现，实际上，程序在输入 `5回车` 之后，并没有立即打印 `x = 5`，然后我们输入字符 `a回车`，之后，程序才一起把

```text
x = 5
ch = a
hello world
```

打印出来了，这就是因为 `scanf` 中的 `\n` 导致的，它会一直等待，直到遇到一个非空白符为止，所以我们在输入 `5回车` 之后，它会继续等待，直到我们输入了 `a`，它才停止读取，然后依次执行后续的输出。

同时各位注意一下，由于 `\n` 在 `scanf` 中的特殊性，建议各位不要在 `scanf` 后加入 `\n` 来吃掉回车，而是使用 `getchar()` 来吃掉回车，这样可以避免很多不必要的麻烦。
